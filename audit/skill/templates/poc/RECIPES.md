# PoC attack recipes (LiteSVM / Mollusk)

| Recipe | Setup | Exploit step | Vulnerable / fixed |
|---|---|---|---|
| Bump enumeration (KV-104) | the program takes `bump: u8` and derives with `create_program_address` | for `b in 0..=255`, if `create_program_address(&[user, &[b]], &pid)` succeeds, send `create(b)` and then `claim(b)` | about half the bumps succeed / exactly one succeeds; the others fail with `ConstraintSeeds (2006)` |
| Same-tx close + refund (KV-106) | a close-after-claim handler | one tx `[claim_and_close(entry), system_transfer(attacker → entry, rent_exempt(len))]`, repeated; test re-creation via `init` separately | rewards accrue on each loop / with Anchor ≥ 0.26.0 `close` (assign to System, data length 0), the second claim fails on the owner check (`AccountOwnedByWrongProgram (3007)`) |
| Clone-program owner bypass (KV-015) | the handler calls `try_deserialize` on an `UncheckedAccount` | `svm.set_account(fake, Account { owner: attacker_pid, data: [sha256("account:Vault")[..8], authority = attacker, …] })`; no clone deployment needed | withdraw succeeds / `AccountOwnedByWrongProgram (3007)` with `Account<'info, Vault>` |
| Unsigned authority (KV-013) | `has_one = authority` with an unchecked `authority` | `AccountMeta::new_readonly(real_authority, false)`, tx signed only by the attacker (do not mark the key as a signer, or the runtime rejects it first) | drain / `AccountNotSigner (3010)` with `Signer<'info>` (or `ConstraintSigner (2002)` with `#[account(signer)]`) |
| Fake config over a real vault (KV-143) | a permissionless `init_pool` stores `vault` + destination; the vault authority PDA is seeded only by `mint` | init a second pool pointing at the existing vault with the attacker's destination, then withdraw | vault drained / the pool-scoped authority cannot sign |
| Many-to-one introspection (KV-151) | the consumer reads a fixed index | `[transfer(PRICE → vault), claim, claim, claim]`; then an attacker program CPIs `claim` 3× | 3 rewards / CPI rejected and one-to-one pairing enforced |
| Mint resurrection (KV-166) | the pool accepts Token-2022 mints | a mint with `MintCloseAuthority` + `NonTransferable` (supply 0); create the vault (it gets `NonTransferableAccount`); close the mint and re-create it at the same address without extensions; deposit; withdraw | withdraw fails forever (the vault account keeps `NonTransferableAccount`) / mint refused, or orphan detected |
| `Program<System>` substitution (KV-154, anchor-lang 1.0.0–1.0.1) | the handler builds a System instruction from the `system_program` account's key | pass the Compute Budget program (an executable builtin in agave v3.0.0 whose processor returns `Ok(())` for any input, including under CPI) in the `system_program` slot | succeeds with no balance change / rejected on 1.0.2+ (`InvalidProgramId (3008)`) |
